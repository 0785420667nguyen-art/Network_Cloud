\section{TỔNG QUAN ĐỀ TÀI}\label{sec:tong_quan}

\subsection{Đặt vấn đề}

Trong bối cảnh công nghệ thông tin phát triển nhanh chóng, hệ thống mạng doanh nghiệp ngày càng trở nên phức tạp với quy mô mở rộng liên tục. Các doanh nghiệp hiện đại thường có cấu trúc phân tán với trụ sở chính và nhiều chi nhánh tại các địa điểm khác nhau, đòi hỏi một hệ thống mạng ổn định, bảo mật và dễ quản lý.

Mạng doanh nghiệp truyền thống thường gặp phải nhiều khó khăn trong quản lý và vận hành:

\subsubsection{Cấu hình thủ công}
Các thiết bị mạng như switch, router thường được cấu hình thủ công thông qua giao diện dòng lệnh (CLI). Mỗi thiết bị cần được cấu hình riêng lẻ, dẫn đến:
\begin{itemize}
    \item Tốn nhiều thời gian và công sức của đội ngũ quản trị
    \item Dễ xảy ra lỗi do con người (human error)
    \item Khó đảm bảo tính nhất quán trong cấu hình giữa các thiết bị
    \item Thiếu khả năng rollback khi có sự cố
\end{itemize}

\subsubsection{Khó mở rộng}
Khi doanh nghiệp phát triển, việc mở rộng hạ tầng mạng gặp nhiều thách thức:
\begin{itemize}
    \item Phải cấu hình lại nhiều thiết bị khi thêm chi nhánh mới
    \item Thiếu tính linh hoạt trong việc phân bổ tài nguyên mạng
    \item Khó khăn trong việc tích hợp các công nghệ mới
    \item Chi phí đầu tư thiết bị phần cứng cao
\end{itemize}

\subsubsection{Quản lý phân tán}
Trong mô hình truyền thống, mỗi thiết bị mạng hoạt động độc lập:
\begin{itemize}
    \item Không có cái nhìn tổng quan về toàn bộ hệ thống mạng
    \item Khó khăn trong việc giám sát và troubleshooting
    \item Thiếu khả năng điều phối tập trung giữa các thiết bị
    \item Không thể thực hiện các chính sách mạng toàn cục
\end{itemize}

\subsubsection{Thiếu tự động hóa}
Các tác vụ quản trị mạng thường xuyên như tạo VLAN, cấu hình định tuyến, quản lý access control đều phải thực hiện thủ công:
\begin{itemize}
    \item Tốn thời gian cho các tác vụ lặp đi lặp lại
    \item Không thể phản ứng nhanh với các thay đổi
    \item Thiếu khả năng orchestration và provisioning tự động
\end{itemize}

\subsubsection{Xu hướng công nghệ mới}
Để giải quyết các vấn đề trên, hai xu hướng công nghệ đang được áp dụng rộng rãi:

\paragraph{Cloud Computing}
Cloud Computing cho phép cung cấp tài nguyên CNTT dưới dạng dịch vụ, mang lại:
\begin{itemize}
    \item Khả năng mở rộng linh hoạt (elasticity)
    \item Tối ưu hóa chi phí (pay-as-you-go)
    \item Truy cập từ mọi nơi
    \item Private Cloud đặc biệt phù hợp với doanh nghiệp cần kiểm soát cao về bảo mật và tuân thủ
\end{itemize}

\paragraph{Software Defined Networking (SDN)}
SDN là kiến trúc mạng mới tách biệt control plane và data plane, mang lại:
\begin{itemize}
    \item Quản lý tập trung thông qua SDN Controller
    \item Khả năng lập trình mạng qua API
    \item Tự động hóa các tác vụ quản trị
    \item Linh hoạt trong triển khai các chính sách mạng
    \item Giảm phụ thuộc vào thiết bị phần cứng cụ thể (vendor lock-in)
\end{itemize}

\subsubsection{Lý do lựa chọn đề tài}
Xuất phát từ nhu cầu thực tiễn của các doanh nghiệp và xu hướng công nghệ hiện đại, đề tài "Xây dựng hệ thống quản lý mạng doanh nghiệp dựa trên SDN và Private Cloud" được lựa chọn nhằm:
\begin{itemize}
    \item Nghiên cứu và áp dụng công nghệ SDN vào quản lý mạng doanh nghiệp
    \item Kết hợp Private Cloud và SDN để tạo ra giải pháp tổng thể
    \item Tự động hóa các tác vụ quản trị mạng
    \item Cung cấp giao diện quản lý tập trung, trực quan
    \item Đánh giá hiệu quả của giải pháp SDN so với mạng truyền thống
\end{itemize}

\subsection{Mục tiêu đề tài}

Mục tiêu tổng quát của đề tài là xây dựng một hệ thống quản lý mạng doanh nghiệp hoàn chỉnh dựa trên công nghệ SDN và Private Cloud, cho phép quản lý tập trung, tự động hóa các tác vụ quản trị và cung cấp khả năng giám sát toàn diện.

Các mục tiêu cụ thể bao gồm:

\subsubsection{Xây dựng mô hình mạng doanh nghiệp}
\begin{itemize}
    \item Thiết kế topology mạng gồm trụ sở chính và các chi nhánh
    \item Mô phỏng kết nối giữa các site qua VPN/GRE Tunnel
    \item Triển khai VLAN để phân đoạn mạng theo phòng ban
    \item Đảm bảo kết nối liền mạch giữa các chi nhánh
\end{itemize}

\subsubsection{Triển khai Private Cloud}
\begin{itemize}
    \item Xây dựng Private Cloud sử dụng Proxmox hoặc OpenStack
    \item Triển khai các máy ảo cho SDN Controller, Database, Web Server
    \item Cấu hình mạng ảo trong môi trường cloud
    \item Đảm bảo tính sẵn sàng cao (High Availability) cho các dịch vụ
\end{itemize}

\subsubsection{Triển khai SDN Controller}
\begin{itemize}
    \item Cài đặt và cấu hình SDN Controller (Ryu hoặc OpenDaylight)
    \item Tích hợp với OpenFlow switch (Open vSwitch)
    \item Xây dựng các module quản lý: topology discovery, flow management, statistics collection
    \item Phát triển Northbound API cho ứng dụng quản lý
\end{itemize}

\subsubsection{Tự động hóa cấu hình}
\begin{itemize}
    \item Tự động tạo và quản lý VLAN
    \item Tự động sinh flow rule dựa trên policy
    \item Tự động cấu hình routing giữa các VLAN
    \item Tự động phát hiện và cấu hình thiết bị mới (Zero-Touch Provisioning)
\end{itemize}

\subsubsection{Xây dựng hệ thống Web quản lý}
\begin{itemize}
    \item Phát triển dashboard hiển thị topology mạng
    \item Giao diện quản lý switch, VLAN, flow rule
    \item Hệ thống giám sát real-time (bandwidth, flow statistics)
    \item Module cảnh báo và notification
    \item REST API để tích hợp với các hệ thống khác
\end{itemize}

\subsubsection{Đánh giá và so sánh}
\begin{itemize}
    \item Đánh giá hiệu năng: throughput, latency, packet loss
    \item So sánh thời gian triển khai với phương pháp truyền thống
    \item Đánh giá khả năng mở rộng (scalability)
    \item Phân tích ưu nhược điểm của giải pháp
\end{itemize}

\subsection{Đối tượng và phạm vi nghiên cứu}

\subsubsection{Đối tượng nghiên cứu}

Đề tài tập trung nghiên cứu và triển khai các công nghệ sau:

\paragraph{Software Defined Networking (SDN)}
\begin{itemize}
    \item Kiến trúc SDN và nguyên lý tách biệt control plane/data plane
    \item Các thành phần: Application Layer, Control Layer, Infrastructure Layer
    \item Giao tiếp giữa các layer thông qua Northbound và Southbound API
\end{itemize}

\paragraph{OpenFlow Protocol}
\begin{itemize}
    \item Giao thức chuẩn để SDN Controller giao tiếp với OpenFlow switch
    \item Flow table, flow entry, match-action paradigm
    \item OpenFlow messages: Packet-In, Packet-Out, Flow-Mod, Stats-Request
\end{itemize}

\paragraph{SDN Controller}
\begin{itemize}
    \item Ryu Controller: Python-based, mã nguồn mở, dễ mở rộng
    \item Hoặc OpenDaylight: Java-based, đầy đủ tính năng, hỗ trợ doanh nghiệp
    \item Các module: Topology Manager, Flow Manager, Statistics Manager
\end{itemize}

\paragraph{Private Cloud Platform}
\begin{itemize}
    \item Proxmox VE: Đơn giản, dễ sử dụng, phù hợp SME
    \item Hoặc OpenStack: Đầy đủ tính năng, phù hợp doanh nghiệp lớn
    \item Quản lý máy ảo, storage, network
\end{itemize}

\paragraph{Virtual Switch}
\begin{itemize}
    \item Open vSwitch: Hỗ trợ OpenFlow, VLAN, GRE/VXLAN
    \item Tích hợp tốt với các nền tảng ảo hóa
    \item Hỗ trợ SDN và network virtualization
\end{itemize}

\paragraph{VPN/GRE Tunnel}
\begin{itemize}
    \item GRE (Generic Routing Encapsulation): Đóng gói packet Layer 3
    \item VPN Site-to-Site: Kết nối an toàn giữa các chi nhánh
    \item IPSec: Mã hóa traffic qua tunnel
\end{itemize}

\paragraph{VLAN}
\begin{itemize}
    \item IEEE 802.1Q: Chuẩn VLAN tagging
    \item Access port và Trunk port
    \item Inter-VLAN routing thông qua SDN Controller
\end{itemize}

\paragraph{Web Management System}
\begin{itemize}
    \item Backend: Python Flask hoặc Django, REST API
    \item Frontend: HTML/CSS/JavaScript, React/Vue.js
    \item Database: MySQL hoặc PostgreSQL
    \item Real-time communication: WebSocket
\end{itemize}

\subsubsection{Phạm vi nghiên cứu}

Đề tài được thực hiện trong phạm vi sau:

\paragraph{Môi trường triển khai}
\begin{itemize}
    \item Mô phỏng trên môi trường Lab/Testbed
    \item Sử dụng máy chủ vật lý hoặc máy ảo để triển khai Private Cloud
    \item Mô phỏng các chi nhánh bằng virtual network
    \item Không triển khai trên hạ tầng doanh nghiệp thực tế
\end{itemize}

\paragraph{Quy mô hệ thống}
\begin{itemize}
    \item 1 trụ sở chính chứa Private Cloud và SDN Controller
    \item 3 chi nhánh kết nối qua tunnel
    \item 5-10 VLAN đại diện cho các phòng ban
    \item 5-20 OpenFlow switch
    \item 50-100 host (máy ảo hoặc container)
\end{itemize}

\paragraph{Chức năng hệ thống}
\begin{itemize}
    \item Quản lý tập trung: switch, host, VLAN, flow rule
    \item Tự động hóa: tạo VLAN, sinh flow rule, routing
    \item Giám sát: topology, bandwidth, flow statistics
    \item Cảnh báo: link down, high traffic, anomaly detection
\end{itemize}

\paragraph{Giới hạn}
\begin{itemize}
    \item Không triển khai trên thiết bị phần cứng thực tế
    \item Không tích hợp với hệ thống legacy
    \item Không xem xét các vấn đề pháp lý, quy trình nghiệp vụ
    \item Chưa tối ưu hóa cho môi trường production
    \item Tập trung vào proof-of-concept và đánh giá khả thi
\end{itemize}

\subsection{Phương pháp nghiên cứu}

Để đạt được các mục tiêu đề ra, đề tài áp dụng phương pháp nghiên cứu khoa học kết hợp lý thuyết và thực nghiệm:

\subsubsection{Nghiên cứu lý thuyết}
\begin{itemize}
    \item \textbf{Thu thập tài liệu:} Nghiên cứu các bài báo khoa học, tài liệu kỹ thuật, RFC (Request for Comments) về SDN, OpenFlow, Cloud Computing
    \item \textbf{Phân tích công nghệ:} So sánh các SDN Controller (Ryu, OpenDaylight, ONOS, Floodlight), các nền tảng Private Cloud (Proxmox, OpenStack)
    \item \textbf{Nghiên cứu kiến trúc:} Tìm hiểu các mô hình mạng doanh nghiệp, best practices trong thiết kế SDN
    \item \textbf{Học hỏi từ các dự án mở:} Nghiên cứu các dự án SDN mã nguồn mở trên GitHub, OpenStack, ONF
\end{itemize}

\subsubsection{Thiết kế hệ thống}
\begin{itemize}
    \item \textbf{Phân tích yêu cầu:} Xác định yêu cầu chức năng và phi chức năng
    \item \textbf{Thiết kế kiến trúc:} Thiết kế tổng thể hệ thống, lựa chọn công nghệ phù hợp
    \item \textbf{Thiết kế mạng:} Vẽ topology, phân bổ IP, thiết kế VLAN
    \item \textbf{Thiết kế database:} Xây dựng ERD, schema cho các bảng
    \item \textbf{Thiết kế API:} Định nghĩa REST API endpoints, request/response format
    \item \textbf{Thiết kế giao diện:} Wireframe, mockup cho website quản lý
\end{itemize}

\subsubsection{Triển khai và mô phỏng}
\begin{itemize}
    \item \textbf{Xây dựng môi trường Lab:} Cài đặt Proxmox/OpenStack, tạo máy ảo
    \item \textbf{Triển khai SDN:} Cài đặt Ryu Controller, cấu hình Open vSwitch
    \item \textbf{Kết nối các thành phần:} Thiết lập OpenFlow channel, GRE tunnel
    \item \textbf{Phát triển ứng dụng:} Viết code Python cho Controller, Flask cho Web
    \item \textbf{Tích hợp và kiểm thử:} Kiểm tra từng module, integration testing
    \item \textbf{Sử dụng công cụ:}
    \begin{itemize}
        \item Mininet: Mô phỏng mạng SDN
        \item Open vSwitch: Virtual switch hỗ trợ OpenFlow
        \item Wireshark: Phân tích packet
        \item iPerf: Đo throughput
        \item Python: Phát triển Controller và Web application
    \end{itemize}
\end{itemize}

\subsubsection{Đánh giá và phân tích}
\begin{itemize}
    \item \textbf{Đánh giá hiệu năng:}
    \begin{itemize}
        \item Đo throughput bằng iPerf
        \item Đo latency bằng ping, traceroute
        \item Đo packet loss rate
        \item Đo CPU, memory usage của Controller
    \end{itemize}
    \item \textbf{Đánh giá chức năng:}
    \begin{itemize}
        \item Kiểm tra các kịch bản: thêm switch, tạo VLAN, thay đổi flow
        \item Test failover khi có link/node failure
        \item Đánh giá khả năng mở rộng
    \end{itemize}
    \item \textbf{So sánh:}
    \begin{itemize}
        \item So sánh thời gian cấu hình với phương pháp truyền thống
        \item So sánh độ phức tạp trong quản lý
        \item Phân tích ưu nhược điểm
    \end{itemize}
    \item \textbf{Phân tích kết quả:}
    \begin{itemize}
        \item Vẽ biểu đồ, bảng số liệu
        \item Phân tích nguyên nhân của các kết quả
        \item Đưa ra kết luận và khuyến nghị
    \end{itemize}
\end{itemize}
